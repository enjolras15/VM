1. このVMは何か

VM（仮想マシン） とは「ソフトウェアで作った架空のコンピュータ」です。このVMは次のものを持っています。

  • 自作のCPU（簡単な命令が19個だけ）
  • 64KBのメモリ
  • 80×25文字のテキスト画面（16色）
  • ネットワークカード（HTTP GETだけできる）
  • 自作のアセンブラ（人間が読める命令 → CPUが読める数字に変換）

ブラウザ上で、「アセンブリ言語でプログラムを書く → 変換 → CPUが実行 → 画面に文字が出る」という、1980年代の8bitパソコンのような体験ができます。

実在CPU（6502やZ80）に似せてはいますが、互換ではありません。命令の種類も形式も独自です。

2. 前提知識

2.1 ビットとバイト

コンピュータは0か1しか扱えません。これをビットと呼び、8ビットまとめたものを1バイトと呼びます。1バイトは 0〜255 の値を表せます（2の8乗=256通り）。

2.2 16進数

2進数は長いので、プログラミングでは16進数をよく使います。16進数は 0〜9 と A〜F（10〜15）の16種類の数字で書きます。

10進 16進 備考
10 0xA
15 0xF 1桁で表せる最大
16 0x10 桁上がり
255 0xFF 1バイトの最大
65535 0xFFFF 2バイトの最大

このVMでは 0x8000 や $8000 のように書きます（どちらも16進数。0xか$が目印）。

2.3 メモリとアドレス

メモリは「番号付きの箱が65,536個並んだもの」です。1つの箱に1バイト入ります。箱の番号がアドレスです（0x0000〜0xFFFF）。

アドレス:  0x0000  0x0001  0x0002  ...  0xFFFF
中身:       [ 02 ]  [ 41 ]  [ 00 ]  ...  [ 00 ]

2.4 ASCIIコード

文字は番号で表します。'A' は65、'0' は48、スペースは32。このVMの画面は、メモリに書かれた番号をそのままASCII文字として描画します。

2.5 プログラムもただのデータ

CPUが実行する「プログラム」も、メモリ上のバイト列にすぎません。CPUは「メモリの先頭から順番に読んで、書かれた番号に従って動く」だけです。

4. メモリマップ

64KB（0x0000〜0xFFFF）を、用途ごとに分けて使っています。

アドレス範囲 用途
0x0000〜 プログラムの置き場所（ここから実行開始）
0x8000〜0x8F9F VRAM（画面の内容。4000バイト）
0xC000 カーソルX座標
0xC001 カーソルY座標
0xC002 （デモで書き込まれるが、ビデオチップは使っていない）
0xC003 背景色（0〜15）
0xC010〜0xC017 NIC（ネットワーク）のレジスタ

0xC000〜0xC0FF は MMIO（メモリマップドI/O）領域です。普通のメモリのように見えて、書き込むと周辺機器（NIC）が反応します（後述）。

それ以外のメモリは全部RAMで、自由に読み書きできます。ROMはありません。つまりプログラム自身も書き換え可能です。

5. CPU

5.1 レジスタ（CPU内部の作業用メモ）

名前 サイズ 説明
A 8bit (0〜255) アキュムレータ。計算や読み書きの中心
X 16bit (0〜65535) インデックスレジスタ。配列の添字、ループカウンタに使う
PC 16bit プログラムカウンタ。次に実行する命令のアドレス

5.2 フラグ（直前の結果のメモ）

フラグ 意味 実際の挙動
Z ゼロ/一致 結果が0（または比較が一致）なら true。分岐に使えるのはこれだけ
C キャリー ADD/SUB で結果が255を超えると true
N ネガティブ SUB で結果が負になると true（ADD等では変わらない）
V オーバーフロー 定義はあるがどの命令も変更しない

分岐命令（JZ / JNZ）が見るのは Z だけです。「より大きい／小さい」で分岐する命令はありません。

5.3 命令の形式：すべて3バイト固定

このCPUの命令は必ず3バイトです。

 バイト0     バイト1       バイト2
┌────────┬────────────┬────────────┐
│オペコード│ オペランド下位 │ オペランド上位 │
└────────┴────────────┴────────────┘
  • オペコード: 何をするか（命令の種類を表す番号）
  • オペランド: 命令の引数（16bit、下位バイトが先 = リトルエンディアン）

引数が要らない命令（HLT、INCなど）も3バイト使います（オペランドは0で埋められます）。

例: STA 0x8000 は、STAのオペコード 0x05、アドレス 0x8000 を下位→上位の順に並べて：

05 00 80

5.4 実行サイクル（fetch → execute）

CPUは1命令ごとに次を繰り返します（CPU.step()）。

  1. fetch: PC番地から3バイト読む（オペコード1バイト＋オペランド2バイト）
  2. PCを3進める
  3. execute: オペコードに応じた処理をする

ジャンプ命令は「PCを3進めたあと」にPCを上書きします。だから JMP loop はlabelの番地へ飛べます。

止まる条件

  • HLT を実行した
  • 実行後に PC + 3 >= 65536（メモリの終端近く）になった
  • 未知のオペコードを実行した → エラーを投げて停止

⚠ メモリは電源投入時に全部0です。オペコード0は NOP（何もしない）なので、プログラムの末尾に HLT を書き忘れると、CPUは0を読み続けて（NOPを実行しながら）メモリの奥へ進んでいきます。必ずプログラムは HLT か無限ループで終わらせてください。

6. 命令リファレンス

記号: [n] = アドレスnのメモリの中身、imm = 即値（数値そのもの）。

6.1 一覧表

オペコード 命令 動作 変わるフラグ
0x00 NOP 何もしない -
0x01 HLT CPUを停止する -
0x02 LDI imm A ← imm（下位8bit） Z
0x03 LDX imm X ← imm（16bit） Z
0x04 LDA addr A ← [addr] Z
0x05 STA addr [addr] ← A なし
0x06 LDA_X addr A ← [addr + X] Z
0x07 STA_X addr [addr + X] ← A なし
0x08 ADD addr A ← A + [addr] Z, C, N
0x09 SUB addr A ← A − [addr] Z, C, N
0x0A CMP addr A と [addr] を比較（Aは変わらない） Z（一致なら true）
0x0B INC A ← A + 1（255の次は0） Z
0x0C DEC A ← A − 1（0の前は255） Z
0x0D INX X ← X + 1 Z
0x0E DEX X ← X − 1 Z
0x0F CPX imm X と imm を比較 Z（一致なら true）
0x10 JMP addr PC ← addr（無条件ジャンプ） -
0x11 JZ addr Z が true なら PC ← addr -
0x12 JNZ addr Z が false なら PC ← addr -

6.2 「即値」と「アドレス」の違い（最重要）

初心者が最もつまずくポイントです。

種類 意味 該当命令
即値（数値そのもの） 書いた数値が直接使われる LDI, LDX, CPX
アドレス（メモリ番地） その番地の中身が使われる LDA, STA, ADD, SUB, CMP, LDA_X, STA_X 
LDI 5         ; A = 5          （5そのもの）
LDA 5         ; A = [5]        （5番地の中身）
ADD 5         ; A = A + [5]    （5番地の中身を足す）
CPX 5         ; X と 5 を比較   （5そのもの）

つまり ADD 3 は「3を足す」ではありません。 定数を足したいときは、まず定数をメモリに置いて（DBで）、その番地を指定します。

    LDI 10
    ADD three      ; A = 10 + [three] = 13
    HLT
three: DB 3

6.3 インデックス付きアクセス（_X）

LDA_X 0x8000 は「0x8000 + X 番地」を読みます。Xを増やしていけば、配列を順番にたどれます。

    LDX 0
    ; X=0: [0x8000], X=1: [0x8001], ...

6.4 比較と分岐の組み合わせ（if文の作り方）

高級言語の if / while に相当する書き方です。

; if (A == [limit]) goto done
    CMP limit
    JZ  done

; if (A != [limit]) goto loop
    CMP limit
    JNZ loop

; for (X = 0; X != 10; X++) { ... }
    LDX 0
loop:
    ; ...処理...
    INX
    CPX 10
    JNZ loop

「大小比較」はできません。等しいか等しくないかだけで判断します。

7. アセンブラ

CPUは数字しか分かりません。人間が LDI 65 と書いたものを 02 41 00 に変換するのがアセンブラです。

7.1 書き方の基本

ラベル:   命令   オペランド   ; コメント
  • ; 以降はコメント（無視される）
  • 空行は無視
  • 命令名は大文字小文字どちらでもOK（ldi も LDI も同じ）
  • ラベル名は大文字小文字を区別する

7.2 ラベル

loop: のように行頭に 名前: と書くと、その位置のアドレスに名前を付けることができます。ジャンプ先やデータの場所を、数字ではなく名前で書けます。

start:
    LDI 1
    JMP start     ; start の番地（ここでは 0x0000）に飛ぶ

ラベルは後ろで定義されていても使えます（前方参照）。アセンブラが2回読むからです。

7.3 オペランドの書き方

書き方 例 意味
10進数 65, -1 そのまま（負数は16bitに丸められる）
16進数 0x41, $41 16進数
文字 'A' ASCIIコード（65）
ラベル loop そのラベルのアドレス
LO(式) LO(msg) 値の下位8bit
HI(式) HI(msg) 値の上位8bit

LO / HI は、16bitのアドレスを8bitレジスタに入れたいときに使います（NICの設定など）。LO HI は大文字で書く必要があります。

式（msg+1 のような計算）は使えません。

7.4 DB ディレクティブ（データを直接置く）

DB は命令ではなく「ここにバイト列を置く」という指示です。変数、定数、文字列テーブルに使います。

zero:  DB 0                  ; 1バイト（値0）
pal:   DB 0, 1, 2, 3         ; 4バイト
text:  DB "HELLO"            ; 5バイト（文字コードが並ぶ）
mix:   DB "Hi", 0            ; 'H' 'i' 0 の3バイト
ch:    DB 'A', 15            ; 65, 15
  • DB が占めるのは指定したバイト数だけ（命令のように3バイトではない）
  • DB で作った領域はRAM上にあるので書き換え可能 → 変数として使える
    LDI 42
    STA counter     ; counter 番地に 42 を保存
    LDA counter     ; 読み戻す
    HLT
counter: DB 0

⚠ DB をプログラムの途中に置くと、CPUがそこを命令として実行してしまうことがあります。HLT や JMP の後ろにデータを置くのが定石です。

7.5 2パス方式の仕組み

  1. パス1: 各行のサイズを数えながら、ラベルの番地を決める（命令は3バイト、DBは指定バイト数）
  2. パス2: ラベルの番地を使って、実際のバイト列を作る

7.6 アセンブルの実例

    LDI 65
    STA 0x8000
    HLT
アドレス バイト 意味
0x0000 02 41 00 LDI 65 （0x41=65）
0x0003 05 00 80 STA 0x8000 （下位00、上位80）
0x0006 01 00 00 HLT

8. 画面

8.1 構成

  • 80列 × 25行のテキスト画面
  • 1文字のマス = 8×16ピクセル → canvas は 640×400
  • 画面データは VRAM（0x8000〜） にあり、ビデオチップがこれを読んで描画する

8.2 VRAMの並び（最重要）

1マスにつき2バイト使います。

 [文字コード][属性] [文字コード][属性] [文字コード][属性] ...
  1マス目              2マス目              3マス目
  • 文字コード: ASCII（0 または 32 のマスは何も描かれない）
  • 属性: 下位4bitが文字色（0〜15）。上位4bitは無視される

マス（行row・列col）のアドレス:

文字: 0x8000 + (row * 80 + col) * 2
属性: 0x8000 + (row * 80 + col) * 2 + 1

例: 1行目の6文字目（row=0, col=5）の文字は 0x8000 + 10 = 0x800A。

⚠ 属性が0だと黒色で、背景（初期は黒）と同化して見えません。 文字を書いたら、必ず属性（例: 15=白）も書いてください。画面に文字が出ない最大の原因です。

8.3 パレット（16色）

番号 色 番号 色
0 黒 8 暗い灰
1 青 9 明るい青
2 緑 10 明るい緑
3 シアン 11 明るいシアン
4 赤 12 明るい赤
5 マゼンタ 13 明るいマゼンタ
6 茶 14 黄
7 明るい灰 15 白

8.4 背景色とカーソル

  • 背景色は画面全体で1色。0xC003 に色番号（下位4bit）を書くと変わる。マスごとの背景色は指定できない
  • カーソルは 0xC000（X）と 0xC001（Y）で位置を指定。範囲内なら、そのマスの下に白い2ピクセルの下線が出る。電源直後はメモリが0なので左上(0,0)に常に表示される

8.5 描画のタイミング

VRAMに書いた瞬間に画面が変わるわけではなく、実行ループが1フレーム分の命令を実行するごとに画面全体を描き直します。

9. 実行の仕組みとUI

9.1 実行ループ

ui.js の runLoop() が、概ね次を繰り返しています。

while (CPUが止まっていない && 停止要求がない) {
    CPUを 16667 命令ぶん実行する
    画面を描き直す
    1秒ごとにログへ速度を出す
    次の画面更新タイミング（requestAnimationFrame）まで待つ
}
  • CLOCK_HZ = 1,000,000（1MHz）、60fps想定 → 1フレームあたり16,667命令
  • ログに出る「cycles」は、実際には実行した命令数（1命令=1サイクルとして数えている）
  • 画面更新（requestAnimationFrame）に同期するので、120Hzのディスプレイでは約2倍速、別タブに切り替えるとほぼ止まる可能性があります
  • ログの eff = ... kHz は、実測の実行速度です

9.2 ボタンと操作

HTMLが渡されていないので、確認できるのは ui.js から分かるものだけです。

操作 内容
Boot & Run （主操作）実行中なら止める → メモリ全消去＆CPUリセット → アセンブル → 0x0000にロード → 実行開始
■ Stop / ▶ Resume 一時停止（PCなどCPU状態はそのまま）／続きから再開
⏻ Power ON/OFF OFFにするとメモリ全消去・CPUリセット・画面を黒にする。ONで再び使える状態に
タブ 複数のソースを切り替えて編集（最後の1枚は閉じられない）
ログ欄 アセンブルエラー、実行速度、停止時のレジスタ値を表示

コード上、runProgram()（「Load & Run」＝カートリッジ差し替え相当）は、実行中に呼ぶとCPUを止めずにメモリだけ書き換えるホットスワップ動作です。この場合、PCが命令の途中を指してしまい、暴走することがあります（ログにも警告が出ます）。普通は Boot & Run を使ってください。

9.3 エラーの種類

ログの表示 原因
Assemble error: Unknown mnemonic: XXX 存在しない命令名
Assemble error: Invalid operand: XXX 解釈できないオペランド（ラベルの綴り間違いなど）
Runtime error: Unknown opcode 0x.. at 0x.. 命令でないデータを実行してしまった（HLT忘れなど）

10. 仮想NIC（HTTP通信）

NICはネットワークカードです。このVMでは、HTTP GETだけができます。専用命令はなく、MMIOレジスタ（0xC010〜）を普通の STA/LDA で読み書きして操作します。

10.1 レジスタ

アドレス 名前 役割
0xC010 CMD コマンド（0=リセット、1=HTTP GET）。書いた瞬間に実行開始
0xC011 STATUS 0=処理中、1=完了、2=エラー
0xC012 / 0xC013 TX_ADDR 下位/上位 送信するURL文字列の場所
0xC014 TX_LEN URLの長さ（最大255）
0xC015 / 0xC016 RX_ADDR 下位/上位 受信データの書き込み先
0xC017 RX_LEN 受信したバイト数（NICが書く）

10.2 使い方の手順

  1. URL文字列をメモリに置く（DB "http://..."）
  2. TX_ADDR、TX_LEN、RX_ADDRを設定する
  3. CMD に 1 を書く
  4. STATUS が 0 でなくなるまで、ポーリング（繰り返し読んで待つ）
  5. STATUS=1 なら、RX_ADDR のメモリに結果（0終端の文字列）が入っている

10.3 例（送信〜待機〜先頭1文字を画面へ）

    LDI LO(url)
    STA 0xC012       ; TX_ADDR 下位
    LDI HI(url)
    STA 0xC013       ; TX_ADDR 上位
    LDI 19           ; URLの長さ
    STA 0xC014

    LDI 0x00
    STA 0xC015       ; RX_ADDR = 0x4000
    LDI 0x40
    STA 0xC016

    LDI 1
    STA 0xC010       ; GET 開始！

wait:
    LDA 0xC011       ; STATUS を読む
    CMP busy         ; 0 (処理中) と比べる
    JZ  wait         ; まだ処理中なら待つ

    LDA 0x4000       ; 受信データの1文字目
    STA 0x8000
    LDI 15
    STA 0x8001
    HLT

busy: DB 0
url:  DB "http://example.com/"

10.4 制限事項

  • 受信は最大255バイトまで（超えた分は切り捨て）
  • 文字は下位8bitに丸められるので、日本語など非ASCII文字は化ける
  • ブラウザの fetch() を使うため、CORS制限を受ける（相手サーバーが許可していないとエラー=STATUS 2）
  • 受信データは RX_ADDR に直接書かれる。プログラム領域などと重なると自分のコードを壊す
  • STATUSの「処理中」を示す値が 0 なので、CMDを書く前のSTATUSも0（初期状態と区別できない）。必ず先にCMDを書いてから待つこと
  • 通信は非同期。CPUは止まらず進み続けるので、結果が必要なら自分でポーリングする

11. 実践チュートリアル

例1：1文字を表示する

    LDI 65           ; 'A'
    STA 0x8000       ; 左上の文字
    LDI 15           ; 白
    STA 0x8001       ; 左上の属性
    HLT

属性を書き忘れると何も見えません（黒文字）。試してみると理解が深まります。

例2：横に10文字並べる（ループ）

    LDX 0
loop:
    LDI 65           ; 'A'
    STA_X 0x8000     ; 文字
    INX
    LDI 15           ; 白
    STA_X 0x8000     ; 属性
    INX
    CPX 20           ; 10マス×2バイト
    JNZ loop
    HLT

Xは「VRAMの先頭から何バイト目か」を表します。1マスごとに2回INXしています。

例3：足し算して結果を表示

    LDI 3
    ADD four         ; A = 3 + 4 = 7
    ADD ascii0       ; A = 7 + 48 = 55 ('7')
    STA 0x8000
    LDI 15
    STA 0x8001
    HLT

four:   DB 4
ascii0: DB '0'       ; '0' の文字コード(48)

「数字の7」と「文字の'7'」は別物で、画面には文字コードを書く必要があります。

例4：背景色を変える

    LDI 1            ; 青
    STA 0xC003
    HLT

例5：文字列を表示する（インターリーブ方式）

このCPUはインデックスレジスタが1つ（X）しかないので、「読む側」と「書く側」を別々に進められません。デモの hello は、文字と属性を交互に並べたテーブルを、VRAMにそのままコピーすることで解決しています。

loop:
    LDA_X msg        ; msg[X] を読む
    CMP zero         ; 0 なら終端
    JZ  done
    STA_X 0x8000     ; VRAM[X] へ書く（同じ X）
    INX
    JMP loop
done:
    HLT

zero: DB 0
msg:
    DB 'H', 15       ; 文字, 属性
    DB 'i', 12
    DB 0, 0          ; 終端

テーブルの並びがVRAMの並び（文字,属性,文字,属性…）とそっくり同じなので、同じXでコピーできます。

テーブル中の属性を0にしてはいけません。コピー中に「0だ、終端だ」と判定されて途中で終わります。

12. デモプログラムの読み解き

ui.js にある5本のデモの概要です。

デモ 内容
hello 例5と同じ方式で "Hello" を5色で表示
fill 背景を赤にして、画面全体を白い 'X' で埋める（4000バイトを2バイトずつ書く）
lines * を2か所に書く（※13章参照：コメントの意図とは違う動きをする）
counter 0123456789 を黄色で表示。DB "0123456789" の文字を順にコピー（※属性にも文字コードが入る）
colors 背景色を16色順に切り替え続ける無限ループ（Stopで停止）。内側の二重ループは単なる「時間待ち」

13. 用語集

VM ソフトウェアで作った仮想のコンピュータ

PC（プログラムカウンタ） 次に実行する命令のアドレス

オペコード 命令の種類を表す番号

アセンブリ言語 機械語を人間が読める名前（LDI等）で書いたもの
ニーモニック LDI, STA のような命令の名前
ラベル アドレスに付けた名前
ディレクティブ CPU命令ではなく、アセンブラへの指示（DB）
リトルエンディアン 複数バイトの値を、下位バイトから先に並べる方式
VRAM 画面表示用のメモリ領域
MMIO メモリの番地に見せかけた、周辺機器の操作窓口
NIC ネットワークカード
ポーリング 完了するまで状態を繰り返し確認すること
ホットスワップ 動作中にプログラム（メモリ）を差し替えること
CORS ブラウザが、別サイトへの通信を制限する仕組み
